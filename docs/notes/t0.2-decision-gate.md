# T0.2 — Ratzilla spike, decision gate report

Commit: `d27649f`. Measured 2026-09-08 on Linux, Chrome (Chrome DevTools MCP), release build.

**Verdict: pass. Proceed to T0.3.** Both budgets are met warm-cache, and the shared-render
assumption held — one `sp_ui::render` drives terminal and browser with no duplicated layout code.
Two ratzilla defects had to be worked around to get there; both are documented below and neither
required forking.

---

## The four measurements

### 1. WASM bundle

| | Bytes | |
|---|---|---|
| raw | 318,594 | |
| gzip -9 | 121,819 | 38% of raw |
| brotli -q 11 | 94,451 | 30% of raw |

Plus `sp-web-host.js` 26,630 B, `index.html` 1,378 B, `font.css` 333 B, and the font at 116,064 B.
**Total over the wire, brotli + font: ~212 KB.**

Use `94,451` as the T0.3 CI size-gate baseline; the +25% ceiling is **118,064 bytes brotli**.

### 2. Time to first paint, warm cache

Served with `immutable` caching on hash-named assets and brotli, which is what `sp-server` will do
at T2.4. Four samples each.

| Condition | First paint | First contentful paint |
|---|---|---|
| No throttling, warm | 44 ms | **~180 ms** (164 / 172 / 184 / 188) |
| Fast 3G, warm | 604 ms | **768 ms** |

The 200 ms budget is specified warm-cache and is **met unthrottled, with ~20 ms of headroom.**

Fast 3G misses it, but not for a reason more optimization fixes: with immutable caching every
asset is served from cache (`transferSize: 0`) and the entire 768 ms is one `index.html`
revalidation round-trip (~570 ms RTT) plus WASM compile. That RTT is the floor for any
network-loaded page. This is precisely what **T2.2's themed static shell** is for — it paints a
correct frame during that window. T2.2 should be treated as required, not optional.

Caching is doing most of the work here and is worth stating: without cache headers, the same warm
Fast 3G load was **1,336 ms**, because each of the four assets burned its own revalidation RTT.
`python -m http.server` sends no `Cache-Control`, so measuring against it understates the real
product by ~570 ms.

### 3. Time to first accepted keystroke

| | |
|---|---|
| Page load → app accepts keystrokes (warm, no throttle) | **~168 ms** (153 / 166 / 169 / 180) |
| Keydown → repainted glyph, steady state | **9.3 ms** |

Budget is 400 ms; **met with 2.4× headroom.** Readiness tracks first paint almost exactly, since
the app is interactive on the same frame it first draws.

Measured against the app's own auto-focus (grid focused, no click), with a `MutationObserver` for
the repaint and real CDP key events — synthetic `KeyboardEvent`s are not accepted, see defect 2.

### 4. Nerd Font glyph coverage

Screenshot: `docs/notes/t0.2-browser-glyphs.png`. Box-drawing, powerline dividers and Font Awesome
icons all render in the browser from the self-hosted font, no tofu, no CDN.

Font: JetBrainsMono Nerd Font Mono, Nerd Fonts v3.5.1, SIL OFL 1.1 (license read from the font's
own `name` table). Subsetted 12,226 → 1,126 codepoints, 2.45 MB TTF → 116,064 B WOFF2. All eight
required codepoints asserted present in the subsetted font's cmap via fontTools, not inferred from
the filename. A fuller 363,220 B subset is kept for later phases that want Devicons/Octicons/Seti.

Terminal and browser render structurally identically — same glyph line, same bordered block, same
links — confirmed by capturing both.

## Defects found

**1. ratzilla 0.3.1 panics on the first redraw after any state change** — `index out of bounds:
the len is 10502 but the index is 10502` at `dom.rs:321`, killing the render loop. `DomBackend`
keeps two size computations that are never synchronized: `cells[]` is built from a real measured
glyph size (`calculate_size`), while `Backend::size()` — the one `ratatui`'s `autoresize()`
consults every frame — returns `window.innerWidth/10, innerHeight/20`, a hardcoded cell-size guess,
minus one. First paint survives by luck; the next draw indexes one past the end.

PR #159 introduced the accurate measurement path without updating `size()` to match. **Unfixed on
upstream `main`** — `git diff v0.3.1 origin/main -- src/backend/dom.rs` is empty.

Worked around inside `sp-web-host` by pinning `Viewport::Fixed` from `window_size()` (which does
return the correct size), because `autoresize()` is a documented no-op for fixed viewports. No
fork, no vendoring. **Worth filing upstream** — the fix is for `size()` to return `self.size`.

**2. Keyboard input required a click.** `DomBackend` attaches its `keydown` listener to the `#grid`
element (`tabindex="0"`), not to `document`, so a fresh page ignored all typing until the user
clicked it. Fatal for a start page whose entire purpose is type-and-go. `sp-web-host` now focuses
the grid on the first frame.

**3. trunk's bundled wasm-opt rejects rustc's default output** — `wasm-validator error ...
unexpected false`, from bulk-memory and nontrapping-fptoint instructions. Disabled at codegen in
`crates/sp-web-host/.cargo/config.toml`. That file is force-tracked because the global gitignore
excludes `.cargo`; without it a fresh clone cannot build the browser target.

## What this implies for later phases

- **T2.2 is required, not optional.** It is the only thing covering the round-trip window on a slow
  network.
- **T0.3's size gate**: 118,064 bytes brotli.
- **T2.4 must ship `immutable` cache headers** on hash-named assets. It is worth ~570 ms per asset
  on a slow link, which is far more than any code-size work will buy.
- Unthrottled headroom is ~20 ms. Phase 1 adds real widgets and `nucleo` to this bundle, so the
  paint budget should be re-measured at the end of Phase 1 rather than assumed to hold.
